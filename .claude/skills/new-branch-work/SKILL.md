# 新規ブランチ作成 & 作業開始

新しいタスクに着手する前に、ローカルの `master` を最新化してからブランチを切る。古い `master` から派生すると、後でマージ時にコンフリクトや、他の人がマージ済みの変更を見落とす原因になるため。

## 手順

1. **作業ツリーの状態を確認する**
   ```bash
   git status
   ```
   コミットされていない変更がある場合は、ユーザーに確認するか、`git stash -u` で退避する（勝手に破棄しない）。

2. **現在のブランチが `master` でなければ切り替える**
   ```bash
   git checkout master
   ```

3. **リモートの最新情報を取得し、ローカル `master` を最新化する**
   ```bash
   git fetch origin
   git pull origin master
   ```
   （fast-forwardできない場合は、ユーザーの作業を上書きしないよう `git status` / `git log` で状況を確認してから対応する。）

4. **最新化した `master` を起点に新しいブランチを作成する**
   ```bash
   git checkout -b <prefix>/<short-description>
   ```
   - ブランチ名のプレフィックスは、このリポジトリの直近のマージ履歴（`feature/`, `refactor/`, `test/` など）に倣い、タスクの内容に応じて選ぶ。
   - `<short-description>` はタスク内容が分かる簡潔な英語のkebab-caseにする。

5. **ブランチ作成後、ユーザーから依頼された作業に着手する。**

## 注意点

- `git pull` 前に必ず `git status` で未コミット変更の有無を確認すること（安全ルールに準拠）。
- リモートに `master` の更新がない場合でも、手順2〜3は毎回実行し、常に最新のmasterを起点にする。
- ブランチを切った後は、作業対象のブランチ名をユーザーに一言伝える。
